The mentalist
learned to act, not just read.

RAGina-T1 is a single-file, CDN-hosted RAG engine that answers from your documents — and now, when the documents run out, it reaches for tools you register and takes action before it replies.

Get the CDN tag → View source on GitHub
EXHIBITS A–D

What's actually in the file

Four capabilities, all in one ~25KB script. No build step, no server changes required.

EXHIBIT A

Document retrieval

A client-side TF-IDF search index. Load documents via a folder, a JSON index, or a URL — RAGina chunks, scores, and retrieves the most relevant passages for any question, entirely in the browser.

core
EXHIBIT B

Tool calling — the agentic core

Register any JS function as a tool. When documents alone can't answer a question, RAGina asks for a tool, runs it, reads the result, and only then replies — a ReAct loop that works with a plain text-completion backend.

new in T1
EXHIBIT C

Headless mode

RAGina.query() returns an answer (with tools) with zero UI. Built for embedding RAGina's reasoning inside your own interface — a phone-call app, a Slack bot, a support console.

new in T1
EXHIBIT D

Chat widget

An optional floating bubble + panel, ready out of the box. Now shows a live "🔧 using toolName…" tag while a tool call is in flight, so tool use is visible, not silent.

core
HOW THE AGENTIC LOOP WORKS

The backend is a plain prompt-in/text-out endpoint — not a structured function-calling API. So the loop runs entirely on the client:

1. Askquestion + tool list go in one prompt
→
2. Decidemodel replies TOOL_CALL or ANSWER
→
3. Actyour JS handler runs, result recorded
→
4. Repeatup to 4 steps, then final ANSWER
DEPOSITION

Usage

Three lines to start answering from documents. A few more to give it hands.

quick-start.html
<!-- 1. include the script -->
<script src="https://cdn.jsdelivr.net/gh/suryasticsai/RAGina@main/ragina-t1.js"></script>

<script>
  // 2. load what it should know
  RAGina.loadData({
    "faq.html": { bodyText: "Refunds take 5–7 business days..." }
  });

  // 3. that's it — the chat bubble is live
</script>
register-a-tool.js
RAGina.registerTool('lookupOrder', {
  description: 'Look up an order by its ID',
  parameters: { orderId: 'string, e.g. "A1234"' },
  handler: async ({ orderId }) => {
    const r = await fetch('/api/orders/' + orderId);
    return r.ok ? await r.json() : 'Order not found.';
  }
});
headless-query.js
// No widget — use RAGina's brain inside your own UI
const { answer, steps } = await RAGina.query('Where is order A1234?');
console.log(answer);   // "Order A1234 shipped yesterday, arriving Thursday."
console.log(steps);    // full trace — which tool ran, with what args

FIELD REPORTS

Business use cases

Anywhere "answer from our docs" isn't quite enough — because the real answer requires checking something live.

01

E-commerce support

Answers shipping/return policy from docs, then calls a tool for the one thing docs can't know: this customer's actual order status.

tool: lookupOrder(orderId) → live status
02

SaaS product docs

Replaces a static docs search bar. When a question needs account-specific info, it calls your API instead of guessing.

tool: getAccountPlan(userId) → current tier
03

Internal knowledge base

Point loadFolder() at exported wiki/HTML pages for instant onboarding Q&A — "who owns the deploy pipeline," "what's our PTO policy."

tool: none required — pure retrieval
04

Voice / phone agents

Headless mode is built for exactly this — plug RAGina.query() behind a speech pipeline for a phone-call-style assistant, no chat widget involved.

tool: checkCalendar(date) → open slots
05

Real estate

Answers listing questions from property docs, then books a live showing instead of just describing how to.

tool: bookShowing(listingId, time) → confirmed
06

Front-desk intake

Answers general policy questions and checks appointment availability. Keep it to logistics — not medical, legal, or financial advice.

tool: checkAvailability(date) → open times
07

Education / tutoring

Answers from course material, then grades a quick check with a tool so the "answer" is actually verified, not just plausible-sounding.

tool: gradeAnswer(question, response) → score
08

Professional services intake

Answers FAQ from your service docs, then hands off to a tool that creates a lead or books a consult — no separate contact form.

tool: createLead(name, need) → CRM entry
CHAIN OF CUSTODY

Getting it via CDN

jsdelivr mirrors the GitHub repo automatically — no separate publish step needed:

index.html
<script src="https://cdn.jsdelivr.net/gh/suryasticsai/RAGina@main/ragina-t1.js"></script>
⚠ @main tracks your latest push live — convenient for testing, risky for production. Tag a release (e.g. v2.2.0) and pin sites to @v2.2.0 instead, so a future push to main can't break anything already deployed.
